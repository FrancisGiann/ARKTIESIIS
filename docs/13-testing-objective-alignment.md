# Phase 13 — Testing Evidence and Objective Alignment

## Scope and evidence standard

This report compares the current application with the objectives as written in [docs/07-paper-objectives-scope-limitations.md](07-paper-objectives-scope-limitations.md). It does not change that source document or convert implementation clarifications into school policy. The objective descriptions below are concise paraphrases; the named source remains authoritative for the paper wording.

Automated route tests run against an ephemeral Express server and service/authentication test doubles unless stated otherwise. Unit and service tests use in-memory SQL harnesses and synthetic files. They are useful behavioral evidence, but they are not production tests or a manual UI review.

## Configured-environment workflow and limits

A **read-only local E2E smoke** passed against the configured local development SQL Server using the existing demo student credentials: password-only development login, database-backed dashboard dispatch/render, own document list, and a denied finance request. A further **16-case local role matrix** passed for the available student (6), registrar (6), and finance (4) accounts, covering the role-specific allowed and denied routes listed above. Neither run made persistent database or file changes. Both exercised the development-only password path, not email 2FA.

This report-card change did not run a live report-card upload, decision, or Gemini API request against the configured database. V2 setup reran without applying changes, and `npm run db:check` verified the active lifecycle schema. The active report-card lifecycle is covered by synthetic-file service and HTTP tests with mocked SQL/Gemini results; it is not represented as a live report-card end-to-end workflow or extraction-accuracy study. Email 2FA and SMTP delivery were not exercised live in this verification.

## Phase 13 status

The Phase 13 applicable automated checks pass: the configured local SQL-backed read-only matrix passed for student, registrar, and finance, the mocked ephemeral HTTP matrix passed its database-administrator cases, and all 284 automated tests pass. V2 setup/check verified the current baseline and v2.002 report-card lifecycle migration. A live report-card upload/precheck/decision flow, live Gemini request, and email 2FA/SMTP delivery were not run in this verification. The manual browser walkthrough is deferred to Phase 14. The objective gaps in Specific Objectives 2 and 4, the deletion difference in Specific Objective 3, and the unmeasured outcome in the general objective are documented evidence; this phase does not change or silently narrow the paper objectives.
