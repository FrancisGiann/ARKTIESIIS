# Active UI and UX review

This inventory covers the current EJS web application for all six roles. It records implemented routes and states, not proposed future work. A route can render a normal, empty, validation, conflict, read-only, or service-error state from the same template; those states are listed where they change what the user sees or can do.

## Product language and shared rules

- The active stack is Node.js, Express, EJS, CSS/JavaScript, and MariaDB. This prototype does not use SQL Server for active application work.
- The roles are database administrator, registrar, front desk, finance, teacher, and student. Server route guards remain authoritative; the navigation only reflects those rules.
- The shared shell preserves the supplied official seal and the full Ark Technological Institute Education System Inc. / Lucena Branch identity. Navigation group headings remain text-only burgundy; selected destinations use the current light selected state.
- Interactive controls use at least 44px targets where they are controls: buttons, form inputs/selects, navigation items, row actions, and disclosures. Checkbox/radio geometry remains native. Inline reading links are not enlarged into button-like controls.
- Paper clearance means a registrar has inspected a fully signed paper form. Its only visible outcomes are **Not completed** and **Completed**. Finance's term account clearance is a separate signed fees/payment decision. Document request fee review is a separate decision before document release. None of these states substitutes for another.
- Automated document prechecks provide limited advisory findings. Staff inspect sources and decide; the interface does not claim authenticity, forgery, signature, seal, or forensic verification.

### Compatibility-only and unreferenced templates

`/registrar/intake/legacy` is a guarded compatibility URL. Its first GET handlers redirect to the current Enrollments and activation workspaces, and its earlier POST guards reject old intake/finalization requests. Later legacy list/form/activation render code is unreachable behind those handlers; `views/records/student-intake-list.ejs`, `views/records/student-intake-form.ejs`, and `views/records/legacy-activation-review.ejs` are retained compatibility-only templates, not active screens, and must not be presented as usable workflow. Current enrollment uses the annual enrollment and paper pre-enrollment routes.

The route source has no active render reference for `views/readmissions/index.ejs`, `views/readmissions/form.ejs`, or `views/records/grade-import.ejs`. Return evaluations use the current Student records routes and view; grade work uses the teacher/registrar submission flow. These templates remain untouched and are not included in active screen coverage. Redirect-only compatibility URLs are recorded as route behavior, not as extra screens.
