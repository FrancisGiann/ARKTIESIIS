## Role and document access matrix

All permissions must be enforced on server routes and every file download. Student identifiers supplied in a URL or form must never substitute for the authenticated student's own record link.

| Role | Good Moral Certificate | Report card | Form 137 | PSA birth certificate |
| --- | --- | --- | --- | --- |
| `student` | Upload, view, check status, and re-upload for own record only | Own active student-origin report cards only; historical archive rows denied | View own physical status and staff instruction; no scan, OCR, or file access | Upload, view, and download for own record; re-upload only student-origin submissions after correction is requested |
| `teacher` | No access | No access; submit corrected SSHS ECR workbook for assigned term/section/subject only | No access | No access |
| `registrar` | Manage, manually review, and download authorized student records | Manually review active student-origin reports; read/download legacy archive only; cannot upload or correct report cards; review teacher grade workbooks separately | Scan physical paper for transient suggestions; record status/instruction; historical files remain staff-only | Upload, manage, manually review, and download authorized student records |
| `database_admin` | Oversee, manage, manually review, and download | Manually review active student-origin reports; read/download legacy archive only; cannot upload or correct report cards; manage teacher assignments only (workbook review/download is registrar-only) | Scan physical paper for transient suggestions; record status/instruction; historical files remain staff-only | Upload, oversee, manage, manually review, and download |
| `finance` | No access | No access | No access | No access |

Students may upload Good Moral Certificates, PSA birth certificates, and report cards only for their own linked record. Students cannot read pre-lifecycle report-card archive rows. New report cards enter the bounded Gemini worker for visible-name comparison and PDF/JPEG/PNG format checking; staff then inspect the source and make each decision. The report-card precheck requests no grade fields, writes no grades, and can be retried by staff only for eligible transient failures; after a correction request, the student may upload a revision that re-enters the worker. Teachers submit corrected SSHS ECR XLSX workbooks to the registrar for assigned term/section/subject contexts. The registrar alone can review/download the submitted workbook; database administrators can manage assignments but cannot review/download workbook contents. This workflow stores the original workbook and parsed snapshot privately, creates no grades on teacher submission, and permits a correction revision only after the registrar requests one. Registrar approval rechecks the active assignment, current enrollment/subject roster, and grade snapshot in a serializable transaction; grades become visible to students only after approval. An inactive teacher loses access, but the registrar can finish a pending submission if the assignment remains active; assignment revocation blocks approval. Students see correction instructions for student-origin submissions; correction instructions and reasons for staff-origin PSA files remain staff-only. “Manage” permits the authorized staff workflow for a school record; it does not grant a student access to another student's records. Form 137 status history records a human decision and instruction; a missing staff event displays “Not recorded.” Staff send scan bytes to a CSRF-protected endpoint for temporary processing; the scan is not retained as an uploaded document and no OCR result is saved. Keep historical Form 137 files staff-only. Record material upload, re-upload, review decision, assignment change, and status change through audit events without logging document contents, extracted text, instructions, secrets, raw LRNs/grades, or raw command/database errors.

## Phase 8 — Document Management

1. Inspect the current document schema and application conventions before changing them. Confirm the upload size limit, storage location, and any institution-approved retention requirements; do not invent retention or naming policy.
2. Add role-protected upload, list/detail, download, review handoff, and re-upload routes and matching views. Students upload their own Good Moral Certificates and PSA birth certificates. Staff upload those types for student records. Pre-lifecycle report-card rows are staff-only archive records; new student-origin report-card submissions enter the bounded Gemini worker for visible-name/file-format checks followed by manual staff review. The report-card schema/prompt must not request grades, and this workflow must not write grades. Teachers submit grade workbooks through the separate assignment/review workflow described above. Form 137 has no persistent file upload, but staff may temporarily scan its physical paper for OCR suggestions. Use CSRF protection for mutations and repeat active-role and ownership checks inside service writes where the existing pattern does so.
3. Accept only PDF, JPEG, and PNG. Validate the extension, declared MIME type, actual file signature where applicable, and configured size limit on the server. Reject missing, empty, oversized, or mismatched uploads with a user-safe message.
4. Generate opaque stored names. Store files outside the public directory and resolve every path beneath the configured storage root. Never render a filesystem path. Download handlers must recheck role and record ownership before streaming a file.
5. Persist the existing metadata: student, selected document type, original filename, opaque stored filename, MIME type, byte size, uploader/source, status, and timestamp. Clean up an unreferenced file if the database write fails; report a safe error if cleanup also fails.
6. Treat each corrected permitted digital upload as a new immutable submission. Students may re-upload their own Good Moral Certificates, student-origin PSA files, and report cards only after staff requests correction; registrar/database administrators may submit linked corrections for Good Moral Certificates and PSA certificates. Preserve previous files and validation history. Legacy report-card rows are staff-only archive reads and never enter worker/retry queries; new student-origin submissions use the limited report-card name/file-format precheck and manual staff review. Form 137 changes append a physical status event and never create or replace a file.
7. Build student history/status views and staff search/review views under the role matrix above. Students may view/download PSA files for their own records. Do not expose OCR output or staff-only decision notes to students.

## Phase 9 — Historical local OCR implementation (inactive)

The following local OCR design and acceptance notes describe the earlier Tesseract/Poppler path. They are retained as project history and do not describe or gate the active V2 Gemini precheck pipeline.

1. Require a successful real native OCR run on the local Linux environment, using Tesseract with English trained data and Poppler's `pdfinfo`/`pdftoppm`. Configure executable paths, language, timeout, and concurrency through runtime environment settings. Windows paths may contain spaces and must be passed directly without a shell; their mocked path-handling tests are compatibility coverage and do not replace the Linux run.
2. Keep uploads in private storage. Copy a verified regular file to a private temporary directory, call Tesseract directly for JPEG/PNG, and use `pdfinfo` then page-by-page `pdftoppm` rendering plus Tesseract for PDFs. Clean rendered pages immediately and always remove the private temporary directory.
3. Enforce a technical 20-page PDF maximum (`OCR_MAX_PDF_PAGES` may lower it), bounded render dimensions/output, a bounded timeout that aborts active subprocesses, and bounded worker concurrency. Preserve the existing configurable 10 MB upload default.
4. Upload handlers schedule background work and return without waiting for OCR. Startup and periodic scans recover stale leases and drain pending digital rows. Historical Form 137 rows are excluded from OCR claim and recovery queues; temporary physical scans bypass those queues. Claim one row atomically under SQL Server read-committed locking so parallel workers do not process a submission twice.
5. Persist normalized extraction results in `document_validations`; limit access to extracted text because it contains student information. Handle empty OCR, malformed/encrypted/over-limit PDFs, missing tools, timeout, and processing errors with fixed safe messages. Do not save partial PDF text as a completed result or expose raw command/database errors.
6. Do not classify documents or infer authenticity. Extracted fields are untrusted input: escape them in views and pass only the uploader-selected type to advisory checks. Store possible school-name candidate lines as bounded, escaped staff suggestions. The report-card response schema requests only the visible student name; report-card prechecks do not suggest or write numeric grades. Authorized staff can enter grades through the academic-record workflow, and the registrar-reviewed corrected SSHS E-Class Record import described below is another grade source.

## Phase 10 — Advisory Checks and Human Review

1. Active implementation surfaces a bounded Gemini linked student-name clue for Good Moral Certificates, PSA birth certificates, and active student-origin report cards. Good Moral also receives possible school-name and certificate-context clues; PSA and report cards do not. Report-card prechecks request no grade data; staff use a separate manual source-inspection checklist, while legacy archive rows remain read-only and outside precheck/retry. Form 137 has no school-name requirement; its temporary scan may return a possible school-name line as optional advice. The teacher/registrar SSHS E-Class Record process is a separate grade workflow, not document validation. These suggestions do not define school policy or infer approval.
   These clues are advisory. A student-name match does not establish ownership, and a possible school-name line does not establish school-name legitimacy.
2. Before recording `verified` for a Good Moral Certificate, a registrar/database administrator must attest after source inspection that the linked student name and school-name text are visible and legible, the selected type matches the file, and all submitted pages are readable and complete. For PSA, the same checklist applies without the school-name item. For active report cards, staff manually attest that learner name/student number match, grading period or school year is identified, the selected type matches the file, and submitted pages are readable and complete; this does not alter grades. Legacy report-card archive rows are read-only and do not receive new decisions. Active student-origin report cards use a separate manual checklist that does not write grades. These are thesis-owned staff review controls, not OCR checks, institution-defined page requirements, school approval, or proof of authenticity. The checklist is stored with the immutable decision; pre-migration-008 decisions remain unknown. Checklist details are staff-only.
3. Require registrar/database administrator source inspection after OCR and record one immutable manual decision: verify, correction request, or reject. Only manual verification sets `documents.status` to `valid`. A reason is required to verify despite OCR failure or a missed advisory clue. Do not use a whitelist, grade threshold, automated completeness/format rule, or automatic acceptance. Staff may choose correction or rejection using the existing specific instruction/reason controls; the system does not select an outcome when staff cannot confirm a field.
4. Students see only operational status and applicable correction instructions, not extracted fields, checklist details, or internal override notes. Active report cards show name/file-format precheck and staff-review status; archive rows stay hidden. Status labels describe pending/processing precheck, unavailable precheck with staff review required, awaiting staff review, correction requested, staff-verified, and rejected states. They do not imply institution approval or document authenticity.
5. Form 137 uses a separate physical status history with pending, received, verified, correction, and rejected outcomes. “Not recorded” is shown until staff add an event. Registrar/database administrator users can scan the paper for temporary OCR suggestions; the endpoint is CSRF-protected, returns a no-store response, and persists no scan or OCR data. A failure is shown to staff and does not prevent a manual status decision; historical files remain staff-only.
6. Keep decision/status events append-only and auditable. Use document row locks and status checks so OCR completion or recovery cannot overwrite a manual decision. Preserve all historical OCR rows and review history.
